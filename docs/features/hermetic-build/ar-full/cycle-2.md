# Цикл 2: библиотечный модуль, общая папка вывода, минимальный pack, кешируемый BAML

Решения пользователя 2026-10-14 (не пересматривать): см. `night-report-2026-10-14.md`, раздел «Замечания
пользователя». Идентичность с msbuild не приоритет; сателлиты не трогаем; VSIX/Babel/подпись вне охвата.

## Цель

`xake-ar/build.fsx` в один экран на библиотечном модуле; одна папка вывода на бренд+конфигурацию+TFM;
pack из nuspec + `xake.project.json` без msbuild; BAML как кешируемая фаза; перемер матрицы.

## Главный сценарий: все ячейки одним процессом

msbuild собирает четыре ячейки (2 бренда × 2 конфигурации) только по очереди: bin/obj общие, параллельный
запуск невалиден (`full/matrix.md`: 131 с + restore). Xake собирает все ячейки в одном процессе из одного
графа; теоретический предел — время самой долгой ячейки (~25–30 с), то есть 4–5× против msbuild. Здесь
ожидается разгромное преимущество, и здесь же оно пока не получено. Финальная матрица цикла 1 (0.3.8,
94 проекта): `build-par` 103–105 с против 153 с у msbuild (1.46×), и оба чистых прогона упали на гонке
WPF между брендами (S53). Пул при этом насыщен (среднее 13.5 csc на 18 ядрах, простоев нет), критический
путь раздут конкуренцией с 27 до 63 с. Значит, узкое место уже не планировщик, а объём работы:
~350 с CPU на ячейку × 4 ≈ 80 с на 18 ядрах как нижняя граница при текущем способе компиляции.
Рычаги, по убыванию ожидаемого эффекта:

1. **csc server** (`CSC_SERVER=on`, `/shared`): все замеры шли без него; на малых компиляциях сервер давал
   2–4× (`csc-server.md`). Главный рычаг для инкремента (сейчас 0.67–0.95× против msbuild) и для `build-par`.
2. **Не делать лишнюю работу между ячейками**: Debug и Release одного бренда отличаются только defines и
   `/optimize`, бренды — именами и props; общие цели (ресурсы, resgen, BAML, restore, deploy-копии) должны
   вычисляться один раз. Общая папка вывода (этап A) и кешированный BAML (этап D) убирают копирование и
   msbuild-шаг из критического пути.
3. **S53**: markup-проект WPF должен быть per-brand (и per-config), иначе `build-par` невалиден.
4. Профиль пула после 1–3: Gantt/критический путь (`tools/xakestats.fsx`), лимит пула, I/O.

Критерий цикла: четыре чистые ячейки одним процессом ≤ 60 с (≥ 2.5× против msbuild), инкремент не хуже
msbuild, no-op всех ячеек ≤ 3 с.

## Этапы

| # | что | где | критерий готовности |
|---|---|---|---|
| 0 | **Параллельный запуск всех ячеек**: `CSC_SERVER=on` в матрице, S53 per-brand markup, профиль пула, затем общая работа между ячейками (см. выше) | Xake `src/core`, `src/hermetic`; xake-ar матрица | четыре чистые ячейки ≤ 60 с одним процессом, инкремент ≥ msbuild, отчёт с Gantt |
| A | **Раскладка**: `Locks.compileAs`/`deployWith` пишут в общую папку `out/<b>/<cfg>/<tfm>/`; deploy копирует только пакетные рантайм-ассеты, content/test data, config/runtimeconfig/deps.json; per-project папки и `deploy/` удалены | Xake `src/hermetic` | все 94 проекта собираются в общую папку; `dotnet test` net8.0 из неё проходит; число копируемых файлов на ячейку ↓ на порядок |
| B | **Модуль** `Xake.Hermetic.Dotnet.Flow` (или `Templates`): `Flow.rules { brands; configs; projects; root; extraRoots; out }` даёт правила `import::`, `lock::`, `check::`, `build::`, `deploy::`, `pack::`, `clean::`; хелперы брендов (пустой = MESCIUS), логирование dropped, fingerprints | Xake `src/hermetic` + docs | `build.fsx` ≤ 60 строк без workaround-ов; тесты модуля |
| C | **Pack минимальный**: `Pack.fromNuspec nuspec tokens outDir` — токены из описания (id-префикс бренда, версия = assemblyInfo.version + suffix, авторы/лицензия из nuspec), `lib/<tfm>` из общей папки, без `nugetManifest`/psmdcp; `pack-tokens` через msbuild удалить | Xake + xake-ar | 45 nupkg на бренд, состав файлов равен msbuild (байты не сравниваем); pack-часть скрипта ≤ 20 строк |
| D | **BAML кешируемый**: фаза `xaml::<b>::<cfg>` уровня `update-locks`: msbuild XAML-таски → `generated/<b>/<proj>/{*.g.cs,*.baml,.g.resources}` под fingerprints (входы xaml, ссылки, версия тасков); `build` не зовёт msbuild; пересборка только при изменении xaml/ссылок | Xake | чистый `build` без msbuild для WPF; BN2 снят; `Viewer.Wpf`/`WpfViewer` собираются |
| E | **BN1**: apphost не из машины импорта — хранить в описании RID-независимо и брать пак из restore по RID сборки | Xake | лок одинаков на macOS/Linux/Windows; тест |
| F | Переписать `xake-ar/build.fsx` на модуль; переимпорт, перелок; матрица по `tests/model.md` (без идентичности), `tests/results/<дата>-cycle2/results.md`; сравнение с финалом цикла 1 | xake-ar | таблица msbuild / Xake / ratio по ячейкам; число файлов в `out/` |
| G | Критик по A–E; предложение PR-последовательности с учётом п. 1 критики цикла 1 | Xake docs | `critic-cycle-2.md` |

Порядок: A и B параллельно (разные файлы: раскладка в `Locks.fs`/`Desktop.fs`, модуль новый), затем C и D
параллельно, E вместе с D (оба в `Desktop.fs`), F после всех, G в конце. Пакеты: `3.7.9-night`/`0.3.9-night`
после A+B, `…10-night` после C+D+E.

## Не делаем в этом цикле

Побайтовую идентичность (оставляем тесты как есть, не чиним новые расхождения), сателлиты в скрипте,
binding redirects, deps.json для RID-приложений, Windows-прогон, слияние веток (решение пользователя).
