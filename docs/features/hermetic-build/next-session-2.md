# Следующая сессия: реализация по брифу fsc-rework

Стартовый документ для новой сессии Claude Code с чистым контекстом. Написан 2026-10-11 в конце
сессии интервью. Карта документации: [../../index.md](../../index.md), карта папки:
[index.md](index.md).

## Цель

Реализовать декларативную сборку на задачах fsc/csc по [fsc-rework/brief.md](fsc-rework/brief.md):
(а) скрипт и описания проектов, (б) генерация lock, (в) сборка по lock. Порядок и критерии
приёмки задаёт план PR в брифе.

- Решения из `fsc-rework/interview.md` не пересматривать. Если реализация упирается в
  противоречие, нужно остановиться и спросить пользователя.
- Открытые темы из брифа («правила над правилами», Layout вариант B, ML-формат описания,
  версионирование сборок, опциональные debug-библиотеки) без пользователя не решать.
- Решения по API от 2026-09-29..10-07 не открывать (память `hermetic-api-decisions`).
- PR #42 (`pr/build-fsc-lock`) остаётся в своей ветке: не вливать и не закрывать.

## Организация сессии

Оркестратор на Fable (память `orchestrate-only`): сам читает только индексы, этот файл,
последнюю секцию `session.md`, бриф и interview.md. Реализация, тесты и чтение кода идут
через субагентов, каждый в своём worktree. Отчёт субагента — файл или краткая выжимка.

- Один PR = одна ветка = один worktree, папка называется как ветка. Веток `work/*` и `prep/*`
  не заводить. После мержа дать пользователю команду удаления worktree. Таблицу «PR, ветка,
  worktree» вести в `session.md`.
- Небольшие PR в `dev` на OlegZee/Xake, squash. Без force-push и rebase.
- Перед концом сессии обновить `session.md` (где стоим, точный следующий шаг) и `tracker.md`
  (строка на каждый PR плана).
- Вопрос или замечание пользователя — повод обсудить, а не команда менять код (память
  `discuss-before-planning`).
- Отвечать по-русски. Документацию в `docs/` (кроме `-ru` файлов) писать по-английски.

Показать пользователю план PR из брифа одним списком и спросить, с какого начинать и нет ли
изменений. Код писать только после его ответа.
