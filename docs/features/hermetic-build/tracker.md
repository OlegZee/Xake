## Lock stability (raised 2026-09-22, decision: defer until someone diffs locks for real)
- [ ] split the lock file: dependencies (references, analyzers, compiler, imports — rare, reviewed) apart from compilation (args, sources, generated — every PR); framework/SDK its own section. `Lock.Project` in memory stays one record; only `Lock.write`/`parse` change
- [ ] `Generated` content and the commit sha — **investigated on a live worktree of dataengine develop (2026-09-23 night)**: the sha appears nowhere in the lock today. `AssemblyInformationalVersion` is plain `5.5.1` on this repo/SDK (no `+sha`, empirically; page disables the feature explicitly). `sourcelink.json` *is* generated by the SDK's built-in SourceLink (Bitbucket URL with the sha) and passed as `/sourcelink:<path>`, but `sourcelink` is missing from `CscArgs.inputSwitches`, so its content is never captured in `Generated` and `fromlock` never restores it — a real gap: a replay compiles with whatever `sourcelink.json` happens to be on disk. And a new commit does **not** re-import (no tracked input changed): the lock is *stale*, not drifting. To do: (1) add `sourcelink` to `inputSwitches`; (2) ask msbuild for `SourceRevisionId` and tokenize its value in `Generated` content as `$(SourceRevisionId)`; (3) at compile time resolve the token from the project's repo (`.git/HEAD` → ref → sha; worktrees have a `.git` *file*); (4) `Project.import` `needFiles` `.git/HEAD` and the ref file it points to, so a commit re-imports — the lock content stays identical thanks to the token
- [x] SDK policy (reworded 2026-09-23): a well-formed project pins the SDK with `global.json` (exact version, `rollForward: disable`); we **recommend**, never rely on it. Done: `Project.sdkPin` walks up for `global.json`; the import records `SdkPin` and `NETCoreSdkVersion` in the lock `Properties` and warns per project when the SDK is not pinned exactly or the pinned one did not run. dataengine warns: `8.0.100 rollForward:latestFeature`, ran 8.0.425. The lock split will put the compiler in the dependencies part
- [ ] when splitting, also make the content structured instead of the raw tool output: sources, references, defines, options as fields, not a verbatim `csc` argument list. Keep §8c's fidelity by round-tripping at import: the command line rebuilt from the structure must equal msbuild's, or the import fails
