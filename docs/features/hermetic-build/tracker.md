## SBOM package scope (SDP RFC, read 2026-09-23 — `nuget-sbom.md` "Package scope")

The RFC (`SDP/.memory-bank/framework/docs/6-release/sbom-package-scope-nuget.md`, PDR-0010
draft, comments to 2026-10-07) says a *package* SBOM must describe what the customer receives,
not the supplier's restore graph. `Sbom.forAssembly` is restore-scope today, so it is the input
to that rule rather than the deliverable. Items are ordered by what they unblock.

- [ ] **package-scope filter**: a component enters only if it is (a) a file shipped in the nupkg for that TFM, (b) a registry-declared subcomponent of one, or (c) a nuspec-declared dependency of that TFM group. Everything else goes — SDK/reference-assembly packages, `PrivateAssets="all"` analyzers, `CycloneDX.MSBuild`, doc tools, `<frameworkReference>`. Today we emit the whole restore graph with `scope` telling them apart; the rule says do not emit them at all. Affects `Sbom.forAssembly` and the dataengine/page fixtures' expected output
- [ ] **tier 1, physical inventory**: one component per shipped file (`lib/{tfm}/` incl. satellites, `runtimes/*/lib|native`, `contentFiles/`, `analyzers/`, `build*/`, `tools/`) with SHA-256/512 of the shipped bytes, **nested** under `metadata.component.components[]`; plumbing (`_rels/`, `[Content_Types].xml`, nuspec, signature, icon/readme/license, `.xml` docs, `sbom/` itself) excluded. `Pack.entries` already reads a nupkg back, so this is a listing we can produce *and* verify
- [ ] **tier 2, declared dependencies from the nuspec**, not from the graph: name verbatim, the range kept in a `dt:nuget:declaredVersionRange` property, `version`/`purl` still resolvable for scanners, internal `DS.*`/`MESCIUS.*`/`GrapeCity.*` packages one line and never expanded
- [ ] **tier 3: nothing transitive, at any depth** — and `dependencies[]` must never carry an entry whose `ref` is a tier-2 component (an empty `dependsOn` would assert a closure we do not know). Entries for the root and for our own assemblies are allowed and true
- [ ] **declare the boundary**: `compositions` = `complete` over `assemblies` + `incomplete` over `dependencies`, plus an `annotations[]` entry on the root stating that transitive resolution is the consuming product's responsibility. We emit neither today
- [ ] **one SBOM per (package × TFM)** at `sbom/{tfm}/bom.cdx.json` inside the nupkg, JSF-signed. `forPackage` merges per-assembly BOMs into one per nupkg; the unit has to become (package, TFM), which the split lock now makes natural since `Lock.Entry` carries its `Framework`
